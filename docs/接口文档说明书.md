# 接口文档说明书

## 1. 文档说明

本文档说明 photo-monitor 后端 REST API 和 WebSocket 接口。接口基地址由部署域名决定，生产环境通常通过前端 Nginx 同域代理访问。

示例：

```text
https://yuelansuodao.cn
```

## 2. 通用约定

### 2.1 请求格式

普通接口使用 JSON：

```http
Content-Type: application/json
Authorization: Bearer <token>
```

上传接口使用 multipart：

```http
Content-Type: multipart/form-data
Authorization: Bearer <token>
```

### 2.2 认证方式

除登录接口外，业务接口均需要 JWT：

```http
Authorization: Bearer <token>
```

图片、缩略图和文件预览接口还支持 query token：

```text
?token=<token>
```

### 2.3 通用错误

| 状态码 | 说明 |
| --- | --- |
| 400 | 参数错误或业务规则不满足 |
| 401 | 未登录或 token 无效 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 413 | 上传文件过大 |
| 500 | 服务端异常 |

错误响应示例：

```json
{
  "detail": "请先登录"
}
```

## 3. 权限系统

权限格式：

```text
perm:<system>:<department>:<action>
```

system 取值：

- `photos`
- `company_files`
- `study_articles`
- `ledgers`
- `structure`

action 取值：

- `read`
- `create`
- `update`
- `delete`

`department=*` 表示全部部门。管理员角色 `admin` 拥有全部权限。

## 4. 认证接口

### 4.1 登录

```http
POST /auth/login
```

请求体：

```json
{
  "username": "admin",
  "password": "admin"
}
```

响应：

```json
{
  "success": true,
  "token": "<jwt-token>",
  "user": {
    "username": "admin",
    "role": "admin",
    "name": "系统管理员",
    "permissions": []
  }
}
```

权限：无需登录。

### 4.2 当前用户

```http
GET /auth/me
```

响应：

```json
{
  "authenticated": true,
  "user": {
    "username": "zhangsan",
    "role": "employee",
    "department": "运营部",
    "permissions": ["perm:photos:运营部:read"]
  }
}
```

权限：登录用户。

### 4.3 修改密码

```http
POST /auth/change-password
```

请求体：

```json
{
  "old_password": "oldpass",
  "new_password": "newpass"
}
```

响应：

```json
{
  "success": true,
  "user": {
    "username": "zhangsan",
    "role": "employee"
  }
}
```

权限：登录用户。

### 4.4 修改个人资料

```http
PUT /auth/profile
```

请求体：

```json
{
  "phone": "13800000000",
  "name": "张三",
  "id_number": "330000199001010000",
  "birthday": "1990-01-01",
  "home_address": "浙江省杭州市",
  "emergency_contact": "李四 13900000000",
  "certificates": [
    {
      "name": "安全员证",
      "number": "A001",
      "expires_at": "2026-12-31",
      "note": ""
    }
  ]
}
```

响应：

```json
{
  "success": true,
  "user": {
    "username": "zhangsan",
    "name": "张三"
  }
}
```

权限：登录用户。

### 4.5 退出登录

```http
POST /auth/logout
```

响应：

```json
{
  "success": true
}
```

说明：后端不维护 token 黑名单，前端收到响应后清除本地 token。

## 5. 照片接口

### 5.1 查询照片列表

```http
GET /photos
```

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| station | string | 是 | 站点，如 `uploads`、`xiazhan`、`shangzhan` |
| department | string | 否 | 部门 |
| limit | number | 否 | 每页数量，范围 1 到 100，默认 24 |
| cursor | number | 否 | 游标，默认 0 |
| start_date | string | 否 | 开始日期，`YYYY-MM-DD` |
| end_date | string | 否 | 结束日期，`YYYY-MM-DD` |
| start_time | string | 否 | 当日开始时间，`HH:mm` 或 `HH:mm:ss` |
| end_time | string | 否 | 当日结束时间，`HH:mm` 或 `HH:mm:ss` |

响应：

```json
{
  "items": [
    {
      "name": "IMG_20260708103000_001.jpg",
      "url": "/photos/resource/运营部/xiazhan/2026_07_08-2026_07_08/IMG_20260708103000_001.jpg",
      "thumbnail_url": "/thumbnails/运营部/xiazhan/2026_07_08-2026_07_08/IMG_20260708103000_001.jpg",
      "time": 1783487400.0,
      "actual_time": 1783487400.0,
      "actual_time_text": "2026/7/8 10:30:00",
      "filesystem_time": 1783487400.0,
      "size": 204800,
      "folder": "/app/photos/运营部/xiazhan/2026_07_08-2026_07_08",
      "department": "运营部"
    }
  ],
  "next_cursor": null,
  "total": 1
}
```

权限：`photos:read`。

### 5.2 获取原图

```http
GET /photos/resource/{file_path}
```

示例：

```http
GET /photos/resource/运营部/xiazhan/2026_07_08-2026_07_08/IMG_20260708103000_001.jpg?token=<token>
```

响应：图片文件流。

权限：`photos:read`，并且需要具备该图片部门权限。

### 5.3 获取缩略图

```http
GET /thumbnails/{file_path}
```

响应：JPEG 缩略图文件流。

说明：缩略图按需生成，最大尺寸为 `360 x 360`。

权限：`photos:read`，并且需要具备该图片部门权限。

## 6. 上传接口

### 6.1 上传监控照片

```http
POST /uploads
```

请求类型：`multipart/form-data`

表单字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| department | string | 是 | 部门 |
| station | string | 否 | 站点，默认 `uploads` |
| file | file | 是 | 上传文件 |

响应：

```json
{
  "success": true,
  "item": {
    "id": "e1f2...",
    "name": "IMG_20260708103000_001.jpg",
    "department": "运营部",
    "station": "xiazhan",
    "size": 204800,
    "sha256": "abcdef...",
    "url": "/static/运营部/xiazhan/2026_07_08-2026_07_08/IMG_20260708103000_001.jpg",
    "path": "运营部/xiazhan/2026_07_08-2026_07_08/IMG_20260708103000_001.jpg",
    "uploaded_by": "zhangsan",
    "uploaded_at": "2026-07-08 10:30:00",
    "time": 1783487400.0
  }
}
```

权限：`photos:create`、`photos:update` 或 `photos:delete` 任一上传类权限，并且对目标部门具备 `photos:create`。

### 6.2 上传公司文件

```http
POST /uploads/files
```

请求类型：`multipart/form-data`

字段：`department`、`file`

响应：

```json
{
  "success": true,
  "item": {
    "id": "6d2a...",
    "name": "制度.pdf",
    "category": "company_files",
    "department": "运营部",
    "size": 102400,
    "sha256": "abcdef...",
    "path": "company_files/运营部/2026_07_08/制度.pdf",
    "content_type": "application/pdf",
    "uploaded_by": "admin",
    "uploaded_at": "2026-07-08 09:30:00",
    "time": 1783483800.0,
    "url": "/uploads/files/6d2a.../download"
  }
}
```

权限：`company_files:create`、`company_files:update` 或 `company_files:delete` 任一编辑类权限，并且对目标部门具备 `company_files:create`。

### 6.3 查询公司文件

```http
GET /uploads/files
```

响应：

```json
{
  "items": [
    {
      "id": "6d2a...",
      "name": "制度.pdf",
      "category": "company_files",
      "department": "运营部",
      "size": 102400,
      "url": "/uploads/files/6d2a.../download",
      "uploaded_by": "admin",
      "uploaded_at": "2026-07-08 09:30:00"
    }
  ]
}
```

权限：`company_files:read`。

### 6.4 下载公司文件

```http
GET /uploads/files/{upload_id}/download
```

响应：文件流。

权限：`company_files:read`。

### 6.5 预览公司文件

```http
GET /uploads/files/{upload_id}/view
```

响应：文件流，`Content-Disposition: inline`。

权限：`company_files:read`。

### 6.6 删除公司文件

```http
DELETE /uploads/files/{upload_id}
```

响应：

```json
{
  "success": true,
  "item": {
    "id": "6d2a...",
    "name": "制度.pdf"
  }
}
```

权限：`company_files:create`、`company_files:update` 或 `company_files:delete` 任一编辑类权限，并且对目标部门具备 `company_files:delete`。

### 6.7 学习文章接口

学习文章接口与公司文件结构一致，路径如下：

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | `/uploads/study-articles` | 上传学习文章 | `study_articles:create` |
| GET | `/uploads/study-articles` | 查询学习文章 | `study_articles:read` |
| GET | `/uploads/study-articles/{upload_id}/download` | 下载学习文章 | `study_articles:read` |
| GET | `/uploads/study-articles/{upload_id}/view` | 预览学习文章 | `study_articles:read` |
| DELETE | `/uploads/study-articles/{upload_id}` | 删除学习文章 | `study_articles:delete` |

### 6.8 台账接口

台账接口与公司文件结构一致，路径如下：

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | `/uploads/ledgers` | 上传台账 | `ledgers:create` |
| GET | `/uploads/ledgers` | 查询台账 | `ledgers:read` |
| GET | `/uploads/ledgers/{upload_id}/download` | 下载台账 | `ledgers:read` |
| GET | `/uploads/ledgers/{upload_id}/view` | 预览台账 | `ledgers:read` |
| DELETE | `/uploads/ledgers/{upload_id}` | 删除台账 | `ledgers:delete` |


### 7.7 新增部门

```http
POST /admin/departments
```

请求体：

```json
{
  "name": "运营部"
}
```

响应：

```json
{
  "success": true,
  "departments": ["运营部"]
}
```

### 7.8 部门改名

```http
PUT /admin/departments/{name}
```

请求体：

```json
{
  "name": "新运营部"
}
```

响应：

```json
{
  "success": true,
  "usage": {
    "employees": 1,
    "permissions": 3,
    "photos": 24,
    "thumbnails": 24,
    "company_files": 2,
    "study_articles": 5,
    "ledgers": 1,
    "metadata": 8
  },
  "departments": ["新运营部"]
}
```

说明：改名会同步迁移员工、权限、历史照片、缩略图、公司文件、学习交流、台账和上传元数据。目标位置存在同名文件时返回 409，且不会修改原数据。

### 7.9 查询部门关联数据

```http
GET /admin/departments/{name}/usage
```

响应中的 `usage` 包含员工、权限、照片、缩略图、三类办公资料和元数据数量。

`GET /admin/departments` 会同时返回从历史照片、办公资料和上传元数据中发现的旧部门名称，便于修复改名前已经形成的孤立数据。

### 7.10 迁移并删除部门

```http
POST /admin/departments/{name}/merge
```

请求体：

```json
{
  "target": "总部"
}
```

目标部门必须已存在且不能与原部门相同。源部门可以是仍在部门配置中的部门，也可以是仅存在于历史存储中的旧名称。接口会迁移全部关联数据，然后删除原部门。

### 7.11 删除部门

```http
DELETE /admin/departments/{name}
```

响应：

```json
{
  "success": true,
  "departments": []
}
```

说明：仅允许直接删除无关联数据的部门。仍有关联数据时返回 409，`detail.usage` 提供各类关联数量，管理员应调用迁移并删除接口。

### 7.12 手动执行短信提醒

```http
POST /admin/sms/run-reminders
```

响应：

```json
{
  "success": true,
  "result": {
    "sent": [],
    "skipped": [],
    "failed": []
  }
}
```

### 7.13 查询短信日志

```http
GET /admin/sms/logs
```

响应：

```json
{
  "logs": []
}
```

说明：返回最近 200 条日志。

## 9. WebSocket 接口

### 9.1 照片变化推送

```text
GET /ws?token=<token>
```

协议：

- HTTP 环境使用 `ws://<host>/ws?token=<token>`。
- HTTPS 环境使用 `wss://<host>/ws?token=<token>`。

连接权限：登录用户，并具备 `photos:read` 权限。

服务端推送消息：

```json
{
  "type": "new_photo",
  "path": "/app/photos/运营部/xiazhan/2026_07_08-2026_07_08/IMG.jpg"
}
```

客户端处理建议：

- 收到 `new_photo` 后刷新当前照片列表。
- 连接断开后可自动重连。

## 10. 静态资源接口

### 10.1 办公资料静态路径

```http
GET /office-data/{path}
```

说明：后端将 `office_data` 目录挂载为静态资源。业务前端优先使用受控的 `/uploads/.../download` 或 `/view` 接口，以便进行权限校验。

### 10.2 上传客户端下载

```http
GET /downloads/photo-monitor-uploader.zip
```

说明：由前端 Nginx 作为静态文件提供。

## 11. 调用示例

### 11.1 curl 登录并查询照片

```bash
TOKEN=$(curl -s https://yuelansuodao.cn/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin"}' | jq -r .token)

curl "https://yuelansuodao.cn/photos?station=uploads&limit=24" \
  -H "Authorization: Bearer $TOKEN"
```

### 11.2 curl 上传文件

```bash
curl https://yuelansuodao.cn/uploads/files \
  -H "Authorization: Bearer $TOKEN" \
  -F "department=运营部" \
  -F "file=@制度.pdf"
```
