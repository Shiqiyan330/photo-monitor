# 服务器部署方案及方法

## 1. 文档说明

本文档说明 photo-monitor 系统在 Linux 服务器上的部署方案、环境准备、配置方法、启动更新、HTTPS 配置、备份恢复和常见运维命令。

## 2. 部署架构

系统采用 Docker Compose 部署，包含两个容器：

| 容器 | 说明 | 端口 |
| --- | --- | --- |
| photo-backend | FastAPI 后端服务 | 容器内 `8000` |
| photo-frontend | Nginx + 前端静态文件 + 反向代理 | 主机 `80`、`443` |

访问路径：

```text
浏览器
  -> https://域名
  -> photo-frontend(Nginx)
  -> /auth /admin /photos /uploads /structure /ws 等代理到 photo-backend:8000
```

## 3. 服务器要求

建议配置：

| 项目 | 建议 |
| --- | --- |
| 操作系统 | Ubuntu 22.04 LTS 或 CentOS 8+ |
| CPU | 2 核及以上 |
| 内存 | 2GB 及以上 |
| 磁盘 | 根据照片和文件量规划，建议 50GB 起 |
| 网络 | 开放 80、443 端口 |

基础软件：

- Git
- Docker
- Docker Compose 插件或 `docker-compose`

## 5. 首次部署方法

### 5.1 安装依赖

Ubuntu 示例：

```bash
sudo apt update
sudo apt install -y git ca-certificates curl
```

安装 Docker 可按服务器环境使用官方安装方式。安装完成后验证：

```bash
docker --version
docker compose version
```

### 5.2 获取代码

方式一：手动克隆。

```bash
sudo mkdir -p /opt
sudo chown -R "$USER":"$USER" /opt
git clone 项目Git仓库地址 /opt/photo-monitor
cd /opt/photo-monitor
```

方式二：使用项目部署脚本。

```bash
REPO_URL=项目Git仓库地址 BRANCH=main APP_DIR=/opt/photo-monitor sh scripts/deploy.sh
```

### 5.3 配置环境变量

复制示例配置：

```bash
cd /opt/photo-monitor
cp .env.example .env
```

编辑 `.env`：

```bash
nano .env
```

关键配置：

```env
PHOTO_MONITOR_JWT_SECRET=请替换为随机长密钥
SMS_ENABLED=false
ALIYUN_SMS_SIGN_NAME=短信签名
ALIYUN_SMS_BIRTHDAY_TEMPLATE_CODE=SMS_506865121
ALIYUN_SMS_CERT_TEMPLATE_CODE=SMS_506860107
SMS_DAILY_SEND_TIME=09:00
SMS_CERT_REMIND_DAYS_BEFORE=90
SMS_LOG_FILE=office_data/sms_logs.json
ALIBABA_CLOUD_ACCESS_KEY_ID=实际阿里云AccessKeyId
ALIBABA_CLOUD_ACCESS_KEY_SECRET=实际阿里云AccessKeySecret
```

生成 JWT 密钥示例：

```bash
openssl rand -hex 32
```

注意：

- `.env` 不应提交到 Git。
- 生产环境必须修改 `PHOTO_MONITOR_JWT_SECRET`。
- 上线前建议保持 `SMS_ENABLED=false`，确认短信日志无误后再开启真实发送。

### 5.4 准备数据目录

```bash
mkdir -p photo-backend/photos
mkdir -p photo-backend/office_data
```

如果首次部署没有 `users.json`，后端启动时会创建默认管理员账号。默认账号密码由代码初始化逻辑生成，首次登录后应立即修改密码。

### 5.5 配置 HTTPS 证书

当前 Nginx 配置默认使用域名：

```text
yuelansuodao.cn
www.yuelansuodao.cn
```

证书挂载路径：

```text
./certs/yuelansuodao.cn:/etc/nginx/certs:ro
```

容器内需要以下文件：

```text
/etc/nginx/certs/fullchain.pem
/etc/nginx/certs/privkey.pem
```

宿主机对应路径：

```text
/opt/photo-monitor/certs/yuelansuodao.cn/fullchain.pem
/opt/photo-monitor/certs/yuelansuodao.cn/privkey.pem
```

如使用其他域名，需要修改：

```text
photo-monitor/nginx.conf
docker-compose.yml
```

修改项：

- `server_name`
- 证书目录挂载路径

### 5.6 启动服务

```bash
docker compose -f docker-compose.yml up -d --build
```

查看状态：

```bash
docker compose ps
```

查看日志：

```bash
docker logs photo-backend --tail=100
docker logs photo-frontend --tail=100
```

访问：

```text
https://yuelansuodao.cn
```

## 6. Docker Compose 配置说明

当前主配置文件为：

```text
docker-compose.yml
```

核心配置：

```yaml
services:
  photo-backend:
    build:
      context: ./photo-backend
    container_name: photo-backend
    env_file:
      - .env
    expose:
      - "8000"
    volumes:
      - ./photo-backend/photos:/app/photos
      - ./photo-backend/office_data:/app/office_data
      - ./photo-backend/users.json:/app/users.json
    restart: unless-stopped

  photo-frontend:
    build:
      context: ./photo-monitor
    container_name: photo-frontend
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./certs/yuelansuodao.cn:/etc/nginx/certs:ro
    depends_on:
      - photo-backend
    restart: unless-stopped
```

说明：

- 后端不直接暴露到公网，仅供前端 Nginx 容器代理。
- 前端容器暴露 80 和 443。
- `photos`、`office_data`、`users.json` 为持久化数据。
- `restart: unless-stopped` 保证容器异常退出后自动拉起。

## 7. Nginx 反向代理说明

配置文件：

```text
photo-monitor/nginx.conf
```

主要规则：

| 路径 | 代理目标 |
| --- | --- |
| `/auth/` | `photo-backend:8000` |
| `/admin/` | `photo-backend:8000` |
| `/photos` | `photo-backend:8000` |
| `/thumbnails/` | `photo-backend:8000` |
| `/uploads` | `photo-backend:8000` |
| `/structure` | `photo-backend:8000` |
| `/office-data/` | `photo-backend:8000` |
| `/ws` | `photo-backend:8000`，启用 WebSocket upgrade |
| `/` | 前端静态文件，SPA fallback 到 `index.html` |

上传大小：

```nginx
client_max_body_size 200m;
```

静态资源缓存：

```nginx
expires 7d;
Cache-Control: public, max-age=604800;
```

## 8. 更新发布方法

### 8.1 使用 update.sh

进入项目目录：

```bash
cd /opt/photo-monitor
sh update.sh
```

脚本会执行：

1. `git pull --ff-only`
2. `docker compose up -d --build`
3. 输出容器状态
4. 输出后端和前端最近日志

### 8.2 手动更新

```bash
cd /opt/photo-monitor
git pull --ff-only
docker compose -f docker-compose.yml up -d --build
docker compose -f docker-compose.yml ps
```

### 8.3 回滚方法

查看提交记录：

```bash
git log --oneline -n 10
```

切换到指定版本：

```bash
git checkout 要回滚的提交ID
docker compose -f docker-compose.yml up -d --build
```

确认恢复后再决定是否切回分支：

```bash
git checkout main
```

## 9. 短信配置与启用

### 9.1 干跑模式

默认：

```env
SMS_ENABLED=false
```

该模式会生成短信日志，但不会调用阿里云真实发送接口。

管理员可手动触发：

```http
POST /admin/sms/run-reminders
Authorization: Bearer <admin-token>
```

查看日志：

```http
GET /admin/sms/logs
Authorization: Bearer <admin-token>
```

### 9.2 真实发送

确认以下内容后再开启：

- 阿里云 AccessKey 已配置。
- 短信签名审核通过。
- 模板 code 和变量一致。
- 员工手机号、生日、身份证号、证书有效期已核对。
- 干跑日志符合预期。

开启：

```env
SMS_ENABLED=true
```

重启后端：

```bash
docker compose restart photo-backend
```

## 10. 上传客户端部署说明

前端提供客户端下载：

```text
/downloads/photo-monitor-uploader.zip
```

客户端配置项：

- 服务器地址：生产域名，如 `https://yuelansuodao.cn`。
- 用户名和密码：具备照片上传权限的员工账号。
- 部门：上传照片归属部门。
- 站点：默认 `uploads`，也可按目录自动识别 `xiazhan`、`shangzhan`。
- 监听目录：本机照片生成目录。
- TLS 校验：使用域名证书时建议开启；使用 IP 访问 HTTPS 时可能需要关闭。

服务器端需要给上传账号配置：

```text
perm:photos:<部门>:create
```

如还需要查看照片：

```text
perm:photos:<部门>:read
```

## 11. 防火墙与安全建议

### 11.1 端口开放

仅需开放：

```text
80/tcp
443/tcp
```

后端 `8000` 不应直接开放到公网。

### 11.2 安全加固

建议：

- 修改默认管理员密码。
- 设置强 `PHOTO_MONITOR_JWT_SECRET`。
- 仅通过 HTTPS 访问。
- 定期备份数据目录。
- 限制服务器 SSH 登录来源。
- 定期更新系统和 Docker 镜像。
- 不把 `.env`、证书私钥、备份包提交到 Git。

## 15. 常见问题处理

### 15.1 无法访问 HTTPS

检查：

- 域名是否解析到服务器。
- 443 端口是否开放。
- `certs/yuelansuodao.cn/fullchain.pem` 是否存在。
- `certs/yuelansuodao.cn/privkey.pem` 是否存在。
- Nginx 容器日志是否有证书错误。

命令：

```bash
docker logs photo-frontend --tail=100
```

### 15.2 登录失败

检查：

- 用户名密码是否正确。
- `photo-backend/users.json` 是否存在且格式正确。
- `PHOTO_MONITOR_JWT_SECRET` 是否变更导致旧 token 失效。

### 15.3 上传失败 413

说明文件超过大小限制。

检查：

- Nginx `client_max_body_size 200m`。
- 后端 `PHOTO_MONITOR_MAX_UPLOAD_MB`。
- 上传客户端单文件大小。

### 15.4 上传后前端不刷新

检查：

- `/ws` 是否能建立 WebSocket。
- Nginx 是否保留 Upgrade 头。
- 后端 `photos` 目录是否为容器挂载目录。
- 浏览器控制台是否有 WebSocket 连接错误。

### 15.5 短信未发送

检查：

- `SMS_ENABLED` 是否为 `true`。
- 当前时间是否等于 `SMS_DAILY_SEND_TIME`。
- 员工手机号、生日、证书到期日期是否符合规则。
- `office_data/sms_logs.json` 是否已有 success 记录导致跳过。
- 阿里云 AccessKey、签名、模板是否正确。

## 16. 上线检查清单

- `.env` 已配置强 JWT 密钥。
- 管理员默认密码已修改。
- 域名解析正确。
- HTTPS 证书路径正确。
- 80/443 端口开放。
- `photos`、`office_data`、`users.json` 已持久化。
- 上传账号已配置 `photos:create` 权限。
- 备份任务已配置。
- 短信先以干跑模式验证。
- `docker compose ps` 显示两个容器均为运行状态。
