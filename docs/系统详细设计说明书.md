# 系统详细设计说明书

## 1. 文档说明

本文档说明 photo-monitor 系统的总体架构、模块划分、核心流程、安全设计、异常处理和运行设计，适用于开发、测试、部署和运维交接。

## 2. 系统概述

photo-monitor 是一个照片监控与办公资料管理系统，面向景区或企业内部人员使用。系统提供监控照片查看、照片上传、公司文件归档、学习资料管理、台账管理、员工与部门管理、公司架构查看、短信提醒等功能。

系统由三部分组成：

- Web 前端：React + Vite 单页应用，提供登录、仪表盘、照片监控、资料上传、员工管理等界面。
- 后端服务：FastAPI 应用，提供 REST API、WebSocket 推送、文件上传、鉴权、权限校验、定时任务。
- Windows 上传客户端：本地照片目录监听工具，登录后自动上传新照片到服务器。

## 3. 技术架构

### 3.1 技术栈

| 层级 | 技术 |
| --- | --- |
| 前端 | React 19、Vite、Fetch API、WebSocket |
| 后端 | Python 3.12、FastAPI、Uvicorn、Pydantic |
| 鉴权 | JWT，HS256 签名 |
| 存储 | JSON 文件、文件系统目录 |
| 图片处理 | Pillow 缩略图生成 |
| 文件监听 | watchdog |
| 短信 | 阿里云短信 SDK |
| 部署 | Docker、Docker Compose、Nginx |

### 3.2 部署形态

生产部署采用两个容器：

- `photo-backend`：运行 FastAPI 后端，容器内监听 `8000`。
- `photo-frontend`：运行 Nginx，托管前端静态文件并反向代理后端接口，暴露 `80` 和 `443`。

Nginx 负责 HTTPS 终止、静态资源缓存、API 反向代理和 WebSocket 升级。

## 4. 系统模块设计

### 4.1 用户认证模块

对应文件：

- `photo-backend/routers/auth.py`
- `photo-backend/services/auth_service.py`
- `photo-monitor/src/hooks/useAuth.js`

主要职责：

- 用户登录并签发 JWT。
- 恢复当前登录用户信息。
- 修改密码。
- 维护个人资料。
- 前端在 `localStorage` 保存 token，并在请求头中携带 `Authorization: Bearer <token>`。

认证流程：

1. 用户提交用户名和密码到 `POST /auth/login`。
2. 后端校验 `users.json` 中的账号密码。
3. 密码为明文旧数据时，登录成功后自动迁移为 PBKDF2-SHA256 哈希。
4. 后端签发 7 天有效期 JWT。
5. 前端保存 token 并进入系统。
6. 后续请求通过 `Authorization` 请求头鉴权。

JWT 载荷包含：

- `sub`：用户名。
- `iat`：签发时间。
- `exp`：过期时间。
- `iss`：`photo-monitor`。
- `aud`：`photo-monitor-web`。

### 4.2 权限管理模块

权限采用矩阵字符串表达：

```text
perm:<system>:<department>:<action>
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| system | 业务系统，如 `photos`、`company_files`、`study_articles`、`ledgers`、`structure` |
| department | 部门名称，`*` 表示全部部门 |
| action | 动作，支持 `read`、`create`、`update`、`delete` |

管理员角色 `admin` 拥有所有权限。普通员工根据权限矩阵访问模块、部门和动作。

权限校验位置：

- 后端依赖：`photo-backend/routers/deps.py`
- 权限解析：`photo-backend/services/auth_service.py`
- 前端模块展示：`photo-monitor/src/permissions.js`

### 4.3 照片监控模块

对应文件：

- `photo-backend/routers/photo.py`
- `photo-backend/services/photo_service.py`
- `photo-monitor/src/hooks/usePhotoFeed.js`
- `photo-monitor/src/pages/MonitorPage.jsx`

主要功能：

- 按站点、部门、日期、时间段查询照片。
- 分页加载照片列表。
- 返回图片资源和缩略图资源。
- 自动生成缩略图并缓存到 `.thumbnails`。
- 基于部门权限过滤照片。
- WebSocket 接收新照片通知后刷新照片列表。

照片目录结构：

```text
photo-backend/photos/<部门>/<站点>/<日期区间>/<文件名>
```

示例：

```text
photo-backend/photos/运营部/xiazhan/2026_07_08-2026_07_08/IMG_20260708103000_001.jpg
```

照片时间优先从文件名中的 `20yyyyMMddHHmmss` 模式提取，提取失败时使用文件修改时间。

### 4.4 上传模块

对应文件：

- `photo-backend/routers/upload.py`
- `photo-backend/services/upload_service.py`
- `photo-monitor/src/pages/OfficeUploadPage.jsx`
- `uploader/api_client.py`
- `uploader/worker.py`

上传类型包括：

| 类型 | 接口前缀 | 存储目录 | 说明 |
| --- | --- | --- | --- |
| 监控照片 | `/uploads` | `photo-backend/photos` | 上传客户端或具备权限的账号上传 |
| 公司文件 | `/uploads/files` | `photo-backend/office_data/company_files` | 内部文件归档 |
| 学习文章 | `/uploads/study-articles` | `photo-backend/office_data/study_articles` | 学习资料归档 |
| 台账 | `/uploads/ledgers` | `photo-backend/office_data/ledgers` | 台账文件归档 |

上传限制：

- 默认最大文件大小为 200MB，可通过 `PHOTO_MONITOR_MAX_UPLOAD_MB` 调整。
- 文件名和路径片段会过滤非法字符。
- 上传过程先写入临时文件，再原子替换为正式文件。
- 办公资料上传会写入 `office_data/.metadata.json`。
- 照片上传会在默认 10 秒去重窗口内删除同目录重复照片。

### 4.5 员工管理模块

对应文件：

- `photo-backend/routers/admin.py`
- `photo-backend/services/auth_service.py`
- `photo-monitor/src/components/EmployeeManagerPage.jsx`

管理员可进行：

- 员工新增、修改、删除。
- 员工部门、岗位、职级、手机、身份证、生日、住址、紧急联系人维护。
- 员工证书及有效期维护。
- 员工权限矩阵配置。
- 密码初始化或重置。

员工信息存储在 `photo-backend/users.json`。

### 4.6 部门管理模块

对应文件：

- `photo-backend/routers/admin.py`
- `photo-backend/services/department_service.py`
- `photo-monitor/src/components/DepartmentManagerPage.jsx`

管理员可进行：

- 部门新增。
- 部门改名。
- 部门删除。

删除部门前会校验：

- 是否有员工归属该部门。
- 是否有员工权限引用该部门。
- 是否存在与该部门关联的上传资料。

部门数据存储在 `photo-backend/departments.json`。

### 4.7 公司架构模块

对应文件：

- `photo-backend/routers/structure.py`
- `photo-monitor/src/pages/StructurePage.jsx`

主要功能：

- 展示员工及部门架构信息。
- 管理员可查看全部部门。
- 普通员工可查看本人部门及子部门，或根据 `perm:structure:<department>:read` 权限查看指定部门。

### 4.8 短信提醒模块

对应文件：

- `photo-backend/services/sms_service.py`
- `photo-backend/routers/admin.py`

提醒类型：

- 员工生日祝福。
- 员工证书到期前提醒，默认提前 90 天。

运行方式：

- 后端启动时创建后台线程。
- 每分钟检查一次当前时间。
- 当前时间等于 `SMS_DAILY_SEND_TIME` 且当天未执行时，扫描员工提醒。
- `SMS_ENABLED=false` 时为干跑模式，只写日志不真实发送。
- `SMS_ENABLED=true` 时调用阿里云短信。

短信日志存储在 `office_data/sms_logs.json`。

### 4.9 WebSocket 推送模块

对应文件：

- `photo-backend/routers/ws.py`
- `photo-backend/core/connection_manager.py`
- `photo-backend/services/watcher_service.py`

流程：

1. 前端通过 `/ws?token=<token>` 建立连接。
2. 后端校验 token 和照片读取权限。
3. 后端 watchdog 监听 `photos` 目录。
4. 新文件创建时广播：

```json
{
  "type": "new_photo",
  "path": "<server-file-path>"
}
```

5. 前端收到通知后刷新照片列表。

### 4.10 Windows 上传客户端

对应目录：`uploader/`

主要职责：

- 保存服务器地址、token、部门、站点、监听目录等配置。
- 登录并校验 token。
- 监听或定时扫描本地照片目录。
- 只上传最新日期的图片。
- 判断文件稳定后上传，避免上传仍在写入的文件。
- 记录已上传状态，避免重复上传。
- 支持 TLS 校验开关、重试、日志记录。

## 5. 数据流设计

### 5.1 登录数据流

```text
用户输入账号密码
  -> 前端 POST /auth/login
  -> 后端校验 users.json
  -> 后端签发 JWT
  -> 前端保存 token
  -> 前端请求 /auth/me 恢复用户上下文
```

### 5.2 照片查看数据流

```text
用户进入监控照片页面
  -> 前端 GET /photos?station=...
  -> 后端校验 photos:read 权限
  -> 后端扫描 photos 目录
  -> 按部门、日期、时间过滤
  -> 返回照片元数据
  -> 前端加载 thumbnail_url 或 resource_url
```

### 5.3 照片上传数据流

```text
上传客户端发现本地新照片
  -> 判断文件类型、大小、稳定时间、上传状态
  -> POST /uploads multipart/form-data
  -> 后端校验 photos:create 权限
  -> 后端保存到 photos/<部门>/<站点>/<日期区间>
  -> 后端执行短窗口去重
  -> 返回上传结果
  -> 上传客户端记录 uploaded_state.json
  -> 后端文件监听广播 WebSocket 事件
```

### 5.4 办公资料上传数据流

```text
用户在 Web 端选择文件和部门
  -> POST /uploads/files 或 /uploads/study-articles 或 /uploads/ledgers
  -> 后端校验对应系统 create 权限
  -> 文件保存到 office_data/<分类>/<部门>/<日期>
  -> 元数据写入 office_data/.metadata.json
  -> 前端刷新列表
```

## 6. 安全设计

### 6.1 鉴权安全

- JWT 使用 `PHOTO_MONITOR_JWT_SECRET` 签名。
- token 默认 7 天过期。
- 后端对受保护接口统一校验 token。
- 文件预览类接口支持 query token，便于浏览器内嵌预览。

### 6.2 密码安全

- 新密码使用 PBKDF2-SHA256 哈希。
- 迭代次数为 260000。
- 旧明文密码在成功登录后自动迁移为哈希。
- 管理接口不返回真实密码，已加密密码显示为“已加密，无法查看”。

### 6.3 文件安全

- 上传文件名过滤 `< > : " / \ | ? *` 等非法字符。
- 使用固定根目录解析文件，防止路径穿越。
- 资源读取前检查目标路径是否位于允许目录下。
- Nginx 和后端均限制上传大小。
- 预览响应设置 `X-Content-Type-Options: nosniff`。

### 6.4 权限安全

- 后端以权限矩阵作为最终判断依据。
- 前端隐藏无权限模块，但不作为安全边界。
- 管理员接口统一要求 `admin` 角色。
- 普通员工只能访问授权部门或本人部门相关数据。

## 7. 异常处理设计

| 场景 | 处理方式 |
| --- | --- |
| 未登录或 token 无效 | 返回 401 |
| 权限不足 | 返回 403 |
| 文件不存在 | 返回 404 |
| 参数不合法 | 返回 400 |
| 文件过大 | 返回 413 |
| 上传空文件 | 返回 400 |
| 短信发送失败 | 写入失败日志，不中断后端服务 |
| WebSocket 鉴权失败 | 关闭连接，状态码 1008 |

## 8. 后台任务设计

### 8.1 照片目录监听

后端启动后创建守护线程，监听 `photo-backend/photos`。有新文件创建时向在线 WebSocket 客户端广播事件。

### 8.2 历史照片清理

后端启动后创建守护线程，每天 02:00 扫描照片目录，删除文件名可识别且拍摄日期早于当天的照片，并清理空目录。

### 8.3 短信提醒调度

后端启动后创建守护线程，每 60 秒检查一次是否到达发送时间。当天已执行则跳过，避免重复发送。

## 10. 设计约束与后续优化

当前系统采用 JSON 文件和文件系统作为持久化方案，部署简单、维护成本低，适合中小规模内部系统。若后续用户数、并发上传量、资料数量明显增长，建议迁移到关系型数据库或对象存储，并增加审计日志、操作流水、备份恢复校验和集中监控。
